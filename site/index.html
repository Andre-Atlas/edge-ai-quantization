Quantização pós-treino de LLMs pequenos, no dispositivo

Estudo experimental comparando RTN, GPTQ, AWQ e DWQ (mlx-lm) e K-quants (llama.cpp) em modelos de 0,6 a 4 bilhões de parâmetros, num MacBook Pro M5 Pro com 24 GB de memória unificada.

Dados de piloto. Os números abaixo vêm de uma única execução por configuração, só do Qwen3-0.6B em 4 bits, sem repetições nem benchmarks de tarefas. Servem para validar o pipeline, não para conclusões.

1 · Contexto: IA na borda

Rodar um modelo de linguagem no próprio aparelho (a “borda”) evita enviar dados à nuvem e funciona offline. O custo é que o aparelho tem pouco de tudo:

Memória

Os pesos precisam caber na RAM junto com o cache de atenção. Um modelo de 4 bilhões de parâmetros em 16 bits ocupa cerca de 8 GB; em 4 bits, cerca de 2 GB.

Banda de memória

Ao gerar um token por vez (decodificação), o aparelho relê todos os pesos a cada passo. A velocidade tende a ser limitada pela banda, não pelo cálculo; pesos menores significam menos bytes lidos.

Energia

Bateria e calor limitam o uso contínuo. Menos bytes movidos costuma significar menos energia por token. Este estudo ainda não mede energia (veja Melhorias).

A quantização troca os pesos de 16 bits por inteiros de poucos bits (aqui 8, 4, 3 e 2), com escala por grupo de pesos. Ganha-se memória e, potencialmente, velocidade; paga-se com perda de qualidade. A pergunta do estudo é quanto se perde, conforme o método, o bit-width e o tamanho do modelo.

Dispositivo: MacBook Pro com Apple M5 Pro, 24 GB de memória unificada (CPU e GPU compartilham a mesma memória), executando MLX. É um único dispositivo: velocidade e memória não se generalizam a GPUs CUDA, NPUs ou microcontroladores.

2 · Lógica dos testes

Pipeline

  1. Modelopesos em bf16 (referência “fp”)
  2. Calibraçãocalibration_v5: texto público usado por AWQ, GPTQ e DWQ. RTN não usa dados.
  3. QuantizaçãoRTN, GPTQ, AWQ, DWQ · 8/4/3/2 bits · grupo 64
  4. AvaliaçãoWikiText-2 (teste) + velocidade + memória

Calibração e avaliação usam conjuntos distintos: o algoritmo nunca vê o texto em que é medido. Sem isso, a perplexidade ficaria otimista para os métodos que usam dados.

O que cada métrica mede

Perplexidade (WikiText-2)
Quão “surpreso” o modelo fica com o texto de teste (janelas de 2048 tokens, sem sobreposição). Menor é melhor.
Razão PPLfp/PPLq
Qualidade relativa ao próprio modelo bf16: 1,00 = sem perda; 0,90 = a perplexidade subiu cerca de 11%. É a medida de “qualidade” usada nos gráficos, com a ressalva de que a definição operacional final ainda está pendente.
Prefill (tokens/s)
Velocidade de ler o prompt (512 tokens), em paralelo; tende a ser limitada por cálculo.
Decode (tokens/s)
Velocidade de gerar (128 tokens), um por vez; tende a ser limitada pela banda de memória. Média de 5 repetições após 1 de aquecimento; as barras de erro são o desvio-padrão.
Pico de memória (GB)
Máximo de memória unificada usada pelo MLX durante a geração.
Tamanho (GB)
Tamanho do modelo em disco.

5 · Pontos de melhoria

O que ainda falta ou pode ampliar o estudo:

  • Quantização de ativações. Hoje só os pesos são quantizados. O mlx_lm.benchmark tem --quantize-activations; a ideia vem do SmoothQuant (mover a dificuldade das ativações para os pesos).
  • Formatos de ponto flutuante de micro-escala. mxfp4, nvfp4 e mxfp8, via --q-mode, comparados aos inteiros com escala por grupo.
  • Bits mistos. Predicados como --quant-predicate mixed_3_4 mantêm camadas sensíveis em mais bits.
  • Ablação de group size e da calibração. Variar o tamanho do grupo (32/64/128) e o texto de calibração (tamanho, domínio) para separar o efeito do algoritmo do efeito dos dados.
  • KV-cache e contexto longo. Com contexto longo, o cache de atenção pode superar os pesos em memória; avaliar quantização do cache.
  • Cascata dinâmica + DWQ. Partir de uma quantização dinâmica e refinar com destilação (DWQ).
  • Energia. Medir joules por token com powermetrics (exige sudo).
  • Modelos novos. Qwen3.5, Gemma 4, e os demais do núcleo (Qwen3-1.7B/4B, SmolLM3-3B, Llama-3.2-3B).
  • Mais evidência. Repetições com sementes diferentes e benchmarks de tarefas (lm-eval), além de perplexidade.

6 · Reprodutibilidade

Ambiente com Python 3.14.9 gerenciado por uv; versões travadas em uv.lock.

uv sync
uv run python experimentos/rodar.py --modelo Qwen/Qwen3-0.6B --metodo fp
uv run python experimentos/rodar.py --modelo Qwen/Qwen3-0.6B --metodo rtn  --bits 4
uv run python experimentos/rodar.py --modelo Qwen/Qwen3-0.6B --metodo gptq --bits 4
uv run python experimentos/rodar.py --modelo Qwen/Qwen3-0.6B --metodo awq  --bits 4
uv run python experimentos/rodar.py --modelo Qwen/Qwen3-0.6B --metodo dwq  --bits 4
.venv/bin/python experimentos/exportar_site.py   # atualiza este painel

Cada execução acrescenta uma linha a experimentos/resultados/resultados.csv. O código e os dados estão no repositório Andre-Atlas/edge-ai-quantization.
